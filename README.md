# FiberSense — анализ данных распределённых волоконно-оптических датчиков

Проект для хакатона **«Анализ данных распределённых волоконных сенсоров»**. FiberSense исследует пространственно-временные измерения, выделяет статистически необычные события и показывает взаимосвязи между участками измерительной линии.

> **Важно:** система обнаруживает *статистические аномалии*, а не подтверждённые повреждения кабеля. Единицы X и Y, значение служебного кода `-300`, допустимые рабочие пороги и журнал реальных отказов требуют уточнения у организаторов.

## Что умеет проект

- **Исследование структуры:** чтение вложенного массива `points` из CSV, анализ временной сетки и пространственных профилей.
- **Контроль качества:** поиск пропусков, укороченных профилей, аномальных интервалов и служебных значений.
- **Статистическая норма:** расчёт фонового профиля и отклонений с помощью медианы и MAD.
- **Поиск аномалий:** объединение соседних отклонений по времени и координате в события с указанием их границ, пика и продолжительности наблюдения.
- **Корреляции:** Pearson и Spearman для 10 пространственных зон; проверка линейного тренда и первых разностей.
- **Общий компонент:** диагностика синхронных изменений, PCA и пересчёт корреляций после статистического контроля общей составляющей.
- **Визуализация:** Streamlit-панель, тепловые карты, пространственные профили, временные ряды и таблицы событий.

## Данные

Программа ожидает два файла: `4.csv` и `5.csv`. Они **не входят в репозиторий**; для запуска полного расчёта необходимо получить исходные CSV отдельно и убедиться, что их можно использовать и распространять.

Ожидаемое расположение:

```text
Рабочая_папка/
├── 4.csv
├── 5.csv
└── FiberSense_RU/
    ├── analysis.py
    ├── dashboard.py
    └── ...
```

Файлы содержат поля `dts_id`, `channel_id`, `timestamp` и `points`, где `points` — массив пар `[X, Y]`. Пока документация прибора отсутствует, X следует трактовать как координату измерения, а Y — как измеряемый параметр; их физические единицы **не подтверждены**.

Особенности:
- В `4.csv` встречаются укороченные профили и более длинные интервалы между измерениями.
- В `5.csv` последние 675 координат содержат `-300`; в текущем анализе эти значения считаются недостоверными и исключаются. В коде маскируются значения `Y <= -200`, поэтому правило обработки необходимо согласовать со спецификацией устройства перед промышленным применением.
- В `5.csv` временные метки не содержат явного часового пояса. Не следует автоматически называть их UTC.

## Быстрый запуск (Windows / PyCharm)

Требуется **Python 3.10+**. Откройте папку `FiberSense_RU` как проект PyCharm. Если виртуальная среда `.venv` ещё не создана, создайте её через **Settings → Python Interpreter**.

В терминале PyCharm, находясь внутри `FiberSense_RU`:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe build_ru.py
.\.venv\Scripts\python.exe -m streamlit run dashboard.py
```

После запуска Streamlit откройте **http://localhost:8501**. Для остановки нажмите `Ctrl+C` в терминале. **Если нужны только графики интерфейса, повторно запускать `build_ru.py` необязательно** — достаточно команды Streamlit.

Если PyCharm использует другой интерпретатор, замените `.\.venv\Scripts\python.exe` на `python` или путь к своему интерпретатору.

Для macOS/Linux:

```bash
python3 -m pip install -r requirements.txt
python3 build_ru.py
python3 -m streamlit run dashboard.py
```

**Демо без Python:** откройте `dashboard_demo.html` в браузере. Это уже сгенерированная версия с встроенными данными для демонстрации.

## Верификация и диагностика

Запускайте эти тесты отдельно после установки зависимостей:

```powershell
.\.venv\Scripts\python.exe verify_analysis.py
.\.venv\Scripts\python.exe check_common_mode.py
```

Результаты:
- `verification_results_ru.txt` — тесты искусственно созданных событий, проверка обработки данных и отдельных коэффициентов корреляции с SciPy, изменение порогов.
- `common_mode_results/common_mode_report_ru.txt` — диагностика общей составляющей, PCA и дополнительные проверки.
- `common_mode_results/common_mode_4.png`, `common_mode_results/common_mode_5.png` — сравнительные визуализации.

Проверки кода и искусственных сигналов **не** заменяют проверку на размеченных реальных неисправностях. Для реальной оценки Precision, Recall и F1-score необходимы достоверные метки событий.

## Кратко об алгоритме

1. Преобразование `points` в матрицу «время × координата X» и исключение некорректных значений.
2. Фоновый профиль: медиана значений Y по времени для каждой координаты.
3. Оценка общего сдвига в каждом профиле и расчёт остаточных отклонений.
4. Робастная оценка вариации: `sigma_robust = 1.4826 × MAD`.
5. Кандидаты в аномалии: `|отклонение| > max(3, 5 × sigma_robust)`.
6. Группировка соседних ячеек в пространственно-временные компоненты с фильтрацией небольших групп.
7. Выгрузка координат, времени, пика и длительности наблюдения.

Числа `3` и `5` — **исследовательские настройки алгоритма**, а не нормативные температурные ограничения. Компонентный анализ общего сигнала используется для диагностики корреляций; не следует интерпретировать его как доказательство приборного шума.

## Ограничения

Для инженерной интерпретации необходимо уточнить:
- Единицы измерения X и Y, пространственную привязку и тип измеряемой величины.
- Значение `-300` и допустимый диапазон измерений по документации прибора.
- Часовые пояса и режимы измерения.
- Номинальные температурные пределы, нагрузку кабеля и условия окружающей среды.
- Размеченные реальные события для проверки частоты ложных тревог и пропусков.

**Вывод:** FiberSense обеспечивает воспроизводимый статистический анализ и демонстрацию подозрительных событий, но не выдаёт сертифицированного заключения о техническом состоянии кабеля.
